`demo_website/` is the PyQt demo as a public website, so the app can be shown "like a real user". It has a clickable
390×844 phone and story sections around it, and the build is static files. It isn't in git; commit only when asked.

- **Data:** the site sends `GET https://d1u96rboj5xs6k.cloudfront.net/snapshot`, which is stack `aura-dev-demo-site`
  in `../aws_docs`, branch `dev-demo-site`.
  - It is the only request that leaves the page (Playwright-checked).
  - The response has no email or token.
  - The URL is set in `.env.local` as `VITE_DEMO_API` (public).
  - The bundled fallback is `src/data/sample.json`.
- **Edits:** "read real, edit locally". Visitor changes are an overlay in `localStorage` (`aura-demo:local`), and
  Reset clears it. The site never writes to AWS.
- **Demo account:** `<demo user email (in Secrets Manager aura/dev/demo-site)>` in dev pool `us-west-1_KSpdUo5a7`.
  - The password is only in Secrets Manager `aura/dev/demo-site` and in Credential Manager.
  - It was seeded on 24 Oct through the normal APIs (`tools/seed.py`): the ALL_AT_ONCE month 23 Sep–19 Oct (16
    features alert), 14 days of calendar from 24 Oct, and water.
  - NI-04's alerts are dated on the band days, not on the day they fire.
- **Screens:** Home with the calendar, Recovery, Search with Metric / Logging / Modes / Sessions / Settings / Inbox,
  and the run view. Test lab, sign-in, export and delete are left out. Feature codes appear only in the story.
- **Deliberate differences from PyQt:**
  - Recovery shows one alert per feature (its newest); the seeded month would otherwise list about 95.
  - Times use 24-hour pill pickers.
  - The tab bar stays visible while a run is hidden in the mini bar.
- **Calendar drag (24 Oct, website only so far):** `src/calendar/drag.ts` (maths and what a drop writes) and
  `useDrag.ts` (pointer handling).
  - What can be dragged: timed tasks, events, and to-do rows into the hours. The bottom edge stretches the length,
    but short 15-minute blocks have no handle.
  - Drops snap to 15 minutes. A drop on a grid day keeps the time. Holding at the hours' side edge flips the day;
    holding on ‹ › flips the week or month.
  - Done tasks and block-placed tasks (`blockId` / `scheduledAt`) stay put.
  - A mouse drags after moving 5 px; touch needs a 350 ms hold. Esc cancels.
  - Drops go through `aura.edit.change`, so they stay in the visitor's browser.
  - The PyQt port (`demo/ui/calview.py`, where a drop would PATCH dev) waits for the user's go-ahead.
- **Hosting (24 Oct):** live at https://dctn.github.io/aura_mobile/.
  - Source is on branch `demo-website` of `dctn/aura_mobile`, which the user made public. Branch `demo` stays the
    PyQt app.
  - `.github/workflows/pages.yml` runs on every push to `demo-website`: npm test, then the build (the CloudFront URL
    is passed only to the build), then deploy.
  - Pages source is "GitHub Actions". The `github-pages` environment allows the `demo-website` branch.
  - Tests never use live data (`test.env` clears `VITE_DEMO_API`), because live alerts drift and broke the first CI
    run.
- **Gates:** `npx tsc --noEmit`, `npx vitest run` (268 tests, 27 Oct), `npm run build`.
  - Screenshots: `docs/screenshots`, made by a Playwright walk in headless Edge (msedge, through uv).
